# AI活用クラウドソーシング受注事業 — 事業計画

AIの実行能力（Claude Code）を生産手段として、クラウドソーシングから案件を受注し収益化する事業の運用ドキュメント一式。

**この事業の中核となる考え方: 領域では選ばない。「Claude Codeで完結する構造か」で選ぶ。**

従来のフリーランスは「自分のスキル領域」で案件を選ぶ。この事業は「AIで完結する構造か」で選ぶ。この判定基準を形式化したものが `job-screening.md` であり、他の全ての施策はそこから導出されている。

## 前提条件

| 項目 | 内容 |
|---|---|
| アカウント状況 | 実績あり（数件・評価あり）。**既存評価は再取得不能な最重要資産** |
| 稼働可能時間 | 週10〜20時間（月43〜86時間） |
| 目標月商 | 50,000〜100,000円（手数料差引前） |
| 目標実効時給 | 3,000円/h以上 |
| 主戦場 | **ランサーズとクラウドワークスの両方が稼働中**（いずれも日次の新着通知が着信）。手数料はランサーズが一律16.5%で最も低いため単価帯1〜10万円ではランサーズ優先。ただしランサーズは2026-08-31登録で実績ゼロのため、当面は両方に提案する。ココナラはPhase 2（待ち受け型） |
| 保有資産 | Androidアプリ `mygallery`（約3,000行、GitHub公開） |

## 収益モデル（月商10万円ケース）

| 案件タイプ | 単価 | 件数 | 実働 |
|---|---:|---:|---:|
| GAS / スプレッドシート自動化 | 50,000円 | 1件 | 12h |
| 小規模ツール制作・アプリ改修 | 20,000円 | 1件 | 8h |
| 継続契約（月次データ処理等） | 15,000円 | 2件 | 10h |
| **合計** | **100,000円** | **4件** | **30h** |

- 手取り: 100,000円 × (1 − 0.165) = **83,500円**（ランサーズ）
- 総投下時間: 実働30h + 提案営業15h + 検証5h = **月50時間**（週約12.5時間）
- 稼働枠（週10〜20時間）に収まる

**時間の余剰は「案件を増やす」のではなく、単価改善と再利用資産の蓄積に投下する。** ここが収益が逓増するか横ばいで終わるかの分岐点。

## 実行フェーズ

### Phase 0 — 基盤整備（Week 1 / 約8時間）
- [x] 受注判定チェックリストの作成
- [x] 価格設計・逆算表の作成
- [x] 提案文テンプレートの作成
- [x] AI利用開示ポリシーの策定
- [x] 納品ワークフローの整備
- [x] ポートフォリオ資料の整備
- [x] プロフィール・自己紹介文の作成（3プラットフォーム分）
- [x] 案件通知メールの着信を確認（クラウドワークスの日次おすすめ案件メールが機能中）

**優先順（実態に合わせて並べ替え済み。稼働中のクラウドワークスを先に固める）**
- [ ] 🔴 **ランサーズの通知カテゴリを絞り込む**（https://www.lancers.jp/mypage/receive_email ）
  現状は動画編集・ライティング・データ入力といった **Tier C カテゴリが通知の約9割**を占め、開発系は1日1〜2件しか流れてこない。**週5件のTier A確保を阻む最大の原因**。「AI・システム開発・運用」系を残し、動画・ライティング・タスク系を外す
- [ ] ランサーズの登録スキルを立ち位置（業務自動化軸＋開発対応）に合わせる — 通知カテゴリが偏っているのは登録スキルの偏りが原因の可能性が高い
- [ ] **クラウドワークスに自己紹介文・ひとことアピールを掲載**（`profile-templates.md` からコピー）
- [ ] クラウドワークスのアプリを入れ、検索条件を3枠保存＋プッシュ通知を有効化（`job-sourcing.md`）
- [ ] ポートフォリオに `mygallery` を登録、時間単価を設定
- [x] ランサーズを開設（2026-08-31）／新着通知メールも着信中
- [ ] **ランサーズに自己紹介文を掲載**（`profile-templates.md` からコピー）
- [ ] 認定ランサーのプロフィール項目を全て埋める（写真／表示名／本人確認／機密保持確認／電話確認／ランサーズチェック／スキル／資格）
- [ ] 実案件10件でチェックリストの判定精度を検証 — **7件実施済み**（2026-09-01〜02）
  - Tier C: 動画編集スカウト／米農家ECサイト／くじシステムPM候補／AI研修講師
  - Tier B: WordPress制作（1本5万円・締切9/5）／人件費異常検出AIエージェント（30〜50万円・締切9/7・**給与データは区分3の可能性あり要確認**）
  - 見送り: プロンプトテンプレート集10本（1万円・検証可能性が弱く実効時給が2,000円/hを下回る見込み）
  - **判定に迷いは出ず、フィルタは機能した**

### Phase 1 — 初動と計測（Week 2〜4）
- [ ] **Tier A案件に週5件以上提案**（提案数が最大のボトルネック）
  - ⚠️ **まとめ出しではなく毎日巡回**。1案件に50件以上の応募が集まることがあり、募集直後の提案が有利。溜めた時点で速度の優位を失う
- [ ] 3〜5件を受注・納品
- [ ] 全案件で実効時給を実測し `kpi-log.md` に記録
- [ ] 見積係数を実測値に較正

### Phase 2 — 安定化（Month 2〜3）
- [ ] ココナラにパッケージ商品を出品（型が固まった領域のみ）
- [ ] 継続契約を2〜3件確保
- [ ] 月商50,000〜100,000円に到達

### Phase 3 — 単価改善（Month 4以降）
- [ ] **認定ランサーの取得**（受注率と単価に直結する。プロフィール項目はPhase 0で充足済みのため、残るは実績条件：報酬額が各カテゴリ上位20%／満足度95%以上／完了率90%以上／タスク承認率90%以上。月次審査）
- [ ] 実測データに基づく単価改定（上げ幅は20%まで）
- [ ] 再利用資産の拡充による処理量の拡大
- [ ] 直接取引への移行を検討（手数料16.5〜22%の削減 ＝ 実質2割の単価改善）

## リスクと対処

| リスク | 内容 | 対処 |
|---|---|---|
| **規約違反（最大）** | 案件ごとに「AI利用禁止／要申告」が混在。特にライティング領域。違反は報酬未払い・アカウント停止に直結 | ライティングを主戦場にしない。`ai-disclosure-policy.md` の基準で機械的に判定し、グレーは受けない |
| **検証工程は削れない** | AI出力をそのまま納品すると品質クレームになる。検証こそが付加価値の実体 | 見積時間に検証工程を必ず計上。`delivery-workflow.md` Phase 4 は削らない |
| **機密保持** | 顧客データ・個人情報のAI投入はNDA違反・法令違反になり得る | `delivery-workflow.md` の秘密情報区分。区分3（機微情報）は投入禁止、匿名化できなければ辞退 |
| **単価の下方圧力** | AI活用者の増加で低スキル領域の単価は下落する | 早期に型を作り速度優位を確立。継続契約と直接取引へ移行 |
| **評価の毀損** | 低評価1件の回復コストは、その案件の報酬を上回る | 納期バッファ1.5倍。不確実な案件は受けない |

**この事業では「断ること」が利益を生む。** 低単価案件は検証工程を削れないため実効時給が崩壊し、評価毀損リスクだけが残る。

## 税務について（要確認事項）

月商5〜10万円 ＝ 年60〜120万円の規模になるため、以下は自身で確認・対応が必要。

- 副業の場合、**所得（収入 − 必要経費）が20万円を超えると確定申告が必要**。この規模では確実に該当する
- 開業届と青色申告承認申請書の提出により、最大65万円の青色申告特別控除の対象となり得る（青色申告承認申請は原則として開業から2か月以内）
- ただし**事業所得と雑所得の区分は個別の実態によって判断される**ため、青色申告が使えるかは一律には決まらない
- 住民税の申告は、所得税の申告が不要な場合でも別途必要になることがある
- クラウドソーシング経由の報酬から源泉徴収されている場合の扱いも要確認

⚠️ **上記は一般的な情報であり、税務上の助言ではない。** 実際の判断は税務署または税理士に確認すること。四半期ごとに収支と経費を整理しておく（`kpi-log.md` の四半期レビュー項目）。

## 運用の基本ループ

```
[ユーザー] 案件を見つける                    job-sourcing.md（通知＋保存検索を毎日巡回）
[ユーザー] 募集要項をコピペして Claude に渡す
   ↓
[Claude]   Tier判定                         job-screening.md（3分以内）
           Tier A/B のみ通過。Tier C は提案文を書かない
   ↓       見積もり                          pricing.md（1.5倍バッファ・逆算表）
   ↓       AI申告の要否を判定                ai-disclosure-policy.md
   ↓       提案文の作成                      proposal-templates.md
[ユーザー] 内容を確認して送信 ← 最終責任
[ユーザー] kpi-log.md に提案を記録（落選案件も必ず）
   ↓
受注
[ユーザー] 要件を文章で確定 ← 飛ばさない      delivery-workflow.md Phase 2
[Claude]   実装                              Phase 3
[ユーザー] 検証 ← 削らない。人間が責任を負う   Phase 4
[ユーザー] 納品 ＋ 継続契約の提案             Phase 5
[ユーザー] kpi-log.md に実績を記録
   ↓       振り返り → 該当ドキュメントをその場で改訂   Phase 6
```

**分担の要点**: 見つける・送る・検証する・責任を負うのがユーザー。判定する・書く・作るのがClaude。
巡回の自動化は行わない（理由は `job-sourcing.md`）。

## 検証：この計画が機能しているかの判断基準

計画は読んで納得できることでは検証されない。**数値で検証する。**

### Phase 0 完了時点
実際の募集中案件10件を `job-screening.md` にかけ、Tier A/B/C に迷いなく分類できることを確認する。迷う項目があればチェックリストを改訂する。

### Phase 1 以降（`kpi-log.md` の判断ルールに従う）

| 観測値 | 判定 |
|---|---|
| 週の提案数 < 5件 | ❌ 最優先で回復。他の改善より先 |
| 提案20件で受注0 | ❌ 提案文の冒頭3行と価格帯を見直す |
| 受注率 > 30% | ⚠️ 単価が安すぎる。15〜20%上げる |
| 見積乖離 > 1.5倍が3件連続 | ⚠️ バッファ係数を実測値に置換 |
| 実効時給 < 2,000円/h | ❌ Tier判定が甘い。案件タイプを降格 |
| 低評価を受けた | ❌ 新規受注を止めて原因分析 |
