# プロフィール（自己紹介文）テンプレート

**プロフィールは、一度書けば全ての提案に効き続ける唯一の資産。** 提案文が案件ごとに使い捨てなのに対し、プロフィールは書き直すまで働き続ける。週5件の提案がボトルネックである以上、提案1件あたりの成約率を上げるプロフィールへの投資効果は、他のどの施策よりも高い。

**立ち位置: 業務自動化を看板にし、Android開発を裏付けの実績として置く。**
GAS/VBA を前面に出すのは `job-screening.md` の Tier A 最有力領域と一致し、案件数も確保できるため。開発力は「その自動化ツールを作れる根拠」として機能する。

---

## 全プラットフォーム共通の作文原則

| 原則 | 理由 |
|---|---|
| **検証体制を具体で書く** | 「頑張ります」は全員が書いている。差別化は「何を確認してから渡すか」にしかない |
| **稼働時間を正直に書く** | 無理な納期を約束しないことが、最優先事項である評価の保護に直結する |
| **安さを訴求しない** | `pricing.md` の単価戦略と正面から矛盾する。安さで選ばれた客は安さで去る |
| **AI併用は1〜2文に留める** | 下記「AI記載のルール」参照 |
| **上限文字数の8割以上を使う** | プロフィールの充実度は、そのまま発注者の判断材料になる |

### AI記載のルール（重要）

方針は **「記載する。ただし押し出さない」**。両側のリスクを避ける選択だが、書き方を誤ると両方の悪い面を引き受ける。

**① 見出しを立てない。文の主語は「検証」であって「AI」ではない。**

- ❌ 「【AI活用について】最新のAI技術をフル活用し、高速に納品します！」
  → 押し出しになり、安さ・速さの訴求に読める。値引き交渉と品質不安を同時に招く
- ✅ 「効率化のため開発工程でAI支援ツールを併用していますが、生成結果をそのまま納品することはなく、動作確認は必ず私自身が行います。」
  → 主語は検証体制。AIは従属節に置く

**② AIを速さ・安さの根拠に使わない。** 使った瞬間に単価を自分で切り下げることになる。

**③ 記載しても、提案時の申告は省略しない。** プロフィールは読まれない場合がある。要申告案件では `ai-disclosure-policy.md` の申告文を提案に含める。**プロフィールへの記載は申告の代替にならない。**

**④ 分量は1〜2文。** 独立した段落にすると、それ自体が主張になってしまう。検証について書いた節の末尾に埋め込む。

## 書いてはいけない表現

| 分類 | 禁止例 | 理由 |
|---|---|---|
| AIの押し出し | 「最新AIをフル活用」「AI活用で格安」「AIで高速納品」 | 安さ・速さの訴求になり、値引き交渉と品質不安を同時に招く |
| 安さ訴求 | 「格安」「最安値」「他社より安く」 | `pricing.md` の単価戦略と矛盾する。安さで選ばれた客は安さで去る |
| 事実に反する記述 | 「全て手作業で」「AIは使用しておりません」 | 事実と異なる。不記載は許容されるが、否定は許容されない |
| 守れない約束 | 「24時間対応」「即日納品」「納期は絶対厳守」 | 週10〜20時間の稼働と矛盾する。守れない約束は評価毀損に直結する |
| 中身のない意欲 | 「精一杯頑張ります」「誠心誠意対応します」 | 全員が書いており差別化にならない。検証体制という具体で置き換える |

## 更新トリガー

プロフィールは書いたら終わりではない。以下のタイミングで見直す。

- **案件を3件納品するごと** — 実績欄に具体的な案件種別を追記する（守秘義務の範囲内で）
- **`mygallery` を更新したとき** — `../portfolio/mygallery.md` と記載内容を揃える
- **Tier分類を見直したとき** — 「対応できること」を `job-screening.md` の Tier A と一致させる
- **稼働時間が変わったとき** — 実態と乖離させない
- **四半期レビュー時** — 各プラットフォームの文字数制限・項目仕様の変更を確認する

⚠️ **プロフィールの記載と実際の対応範囲が食い違うと、受注後に無理が生じる。** 記載は常に実態に合わせる。
